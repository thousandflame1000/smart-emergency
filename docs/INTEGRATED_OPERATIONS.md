# 事件處置工作區整合

## 資料責任

人員、物資、需求、資源點、照護關係、打卡與派遣事件仍由原資料表持有。`TopologyWorkspace.document` 是帶有讀取時間的規劃快照，儲存工作區或試算不會寫回營運資料。

`GET /api/workspaces/operational-data` 以一次唯讀請求取得投影。前端依固定 ID 合併，保留手動道路、接駁和圖形位置；不定時上傳，也不在切頁時重新載入工作區。舊 `database-merge` 保留相容，但新介面不再上傳整張圖來更新現況。

| 對象 | 穩定識別碼 | 關係 |
| --- | --- | --- |
| 人員 | `db:person:<User.id>` | 提出需求、持有物資、照護 |
| 需求 | `db:need:<CommunityNeed.id>` | 登記人、分配物資、任務紀錄 |
| 物資 | `db:res:<CommunityResource.id>` | 擁有者、保留或執行中的需求 |
| 資源點 | `db:point:<ResourcePoint.id>` | 原資源點位置與容量資料 |
| 正式關係 | `db:edge:<relation>:<record-id>` | 每次更新可由原紀錄重建 |

同名不等於同一個人或同一批物資，不依名稱自動合併。每筆需求有自己的位置；未填需求位置時標示使用登記人位置。未知座標、數量、庫存與打卡資料都保留未知狀態。

## 物資寫回

在物件詳情使用「編輯正式資料」，先建立前端待寫回清單；這些變更與情境圖分開。`database-diff` 只預覽，`database-push` 才以單次交易套用明確欄位，任一項衝突會拒絕整批。

- 物資只允許名稱、原數量文字、座標、地址、可用狀態；擁有者及品項不能經更新命令偷偷更換。
- 資源點只允許位置與地址；公開設施不推定庫存。
- 版本指紋包含整筆原紀錄。實際 UPDATE 再逐欄比對，因此其他舊程式未修改時間戳的異動仍會造成衝突。
- 已被 `suggested` 或 `matched` 需求保留的物資不能從工作區或原物資管理 API 修改、重新開放或刪除。
- 每次成功寫回留下 `DispatchEvent.action = workspace_inventory` 的前值、變更及操作者。
- 新情境物資要明確選擇擁有者與品項才能登記。前端產生並保留 `inventory_key`，伺服器以 UUIDv5 對應唯一資源主鍵；重送或複製同源物件不重建。不同來源即使使用相同 CSV 物件 ID，也不會因此被錯誤合併。
- 回應遺失時，重送建立命令會連回已建立的資料。更新命令重送若已過期會回 409，沒有第二次異動或稽核紀錄。

數量只接受可確定的非負整數和單一單位，例如 `20箱`、`5瓶`；純數字沿用原系統的「份」。不把箱當瓶，不換算、不把「約20箱（每箱24瓶）」推測成確定庫存。無法解析的登記仍可查閱，但不加入試算。

## 行動流程

1. 讀取現況，從人員或需求追查照護關係、打卡、警報、物資來源。
2. 使用品項、數量、優先級與直線距離做物資分配試算；結果不會扣庫存或通知 LINE。
3. 送出建議時核對原需求和物資版本、品項、單位及數量，再以條件 UPDATE 保留物資；工作區的併發保留操作只能有一筆成功。
4. 工作區「待核准」逐筆核准或退回，沿用原派遣服務。核准先完成唯一狀態轉移與稽核，再發通知；相同核准重送不再通知。
5. 原 LINE／簽章表單任務回報繼續寫入 `CommunityNeed`／`DispatchEvent`。更新現況後，同一需求 ID 呈現執行或完成狀態，詳情列出事件與回報。

## 明確限制

- 原派遣核心仍是一筆需求保留一整筆物資，沒有部分扣庫存與拆單配送。分配引擎可做部分分配試算，但轉正式建議時會拒絕部分分配；不把兩箱試算偷偷變成整單完成。
- 原通知仍是 best-effort 發送。此整合防止同筆核准重送通知，沒有把原流程全面遷移到通知 outbox；程序在核准提交後崩潰，仍可能需要人工補通知。
- 工作區刷新是人工觸發的快照，不是即時串流；其他人的 LINE 回報要更新現況才會顯示。
- 舊工作區第一次讀取時，道路專用物件與關係會轉成一般 legacy 資料，不再參與道路或交通分析。
- 工作區、自動建議及立即手動派遣共用條件式保留操作；跨這些入口測試同一物資只能被保留一次。沒有新增資料庫唯一索引或自動清理既有重複保留紀錄；既有資料須另行稽核，不能擅自合併或刪除。
- 沒有新增權限系統；沿用既有 `DEMO_PASSWORD`／`ADMIN_LINE_LOGIN`。正式站是否開啟仍由部署設定決定。

## 本機驗證

`venv\Scripts\python.exe tests/serve_integrated_workspace.py` 提供 `http://127.0.0.1:8766/`。

僅使用 `.workspace-preview.db` 和明確標示的本機驗證資料；覆寫為假金鑰，停用 lifespan／排程，不讀取正式營運資料。從工作區下拉選單可選「社區營運整合 · 本機驗證資料」。

`venv\Scripts\python.exe tests/workspace_integration_browser_check.py` 會重建這個專用預覽資料庫，檢查實際 UI 流程、桌面與手機畫面、切頁保留情境和小型寫回請求。瀏覽器測試阻擋所有對外非 GET／HEAD 請求。

全程禁止密集上傳、重複部署或大量外部寫入；本次只在本機驗證，沒有 push 或部署。
